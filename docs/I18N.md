# Languages (English + Hindi)

The app's interface is in English (`en`) and Hindi (`hi`), built on `i18next` + `react-i18next`.

## Files

| Path | What |
| --- | --- |
| `src/i18n/index.ts` | i18next setup, `LANGUAGES`, `LanguageCode` |
| `src/i18n/preferences.ts` | The language saved on this device (AsyncStorage) and the "not yet sent to the server" flag |
| `src/context/LanguageContext.tsx` | `useLanguage()`: current language, `setLanguage()`, sync with the account |
| `src/locales/en/translation.json` | English, one object per module (`common`, `nav`, `orders`, `products`, …) |
| `src/locales/hi/translation.json` | Hindi, same keys |
| `src/components/settings/LanguageSelector.tsx` | The language cards (Settings and Get Started) |
| `src/screens/settings/LanguageSettingsScreen.tsx` | Settings › Language & Region |

## Writing UI text

- In a component: `const { t } = useTranslation();` then `t('orders.acceptOrder')`.
- Outside components (lib helpers, validators): `import i18n from '../i18n'` and `i18n.t(...)`, called when the text is needed, never stored at module load.
- Labels in module-level constants are getters, so they read the current language each time:
  `{ key: 'pending', get label() { return i18n.t('common.pending'); } }`
- Counts use plurals: `t('common.productCount', { count })` with `productCount_one` / `productCount_other` keys.
- Values go in through interpolation (`{{name}}`), never by joining translated fragments, so Hindi can order the sentence its own way. For bold or linked words inside a sentence use `<Trans i18nKey="..." components={{ b: <Text style={...} /> }} />` with `<b>…</b>` in the string.
- Never compare against a label (`label === 'Pending'`); compare keys or backend codes.
- Business data is never translated: product, brand, category, customer, supplier and store names, SKUs, barcodes, descriptions. Server error messages are shown as the server sends them.
- Every key added to `en` must be added to `hi`; `__tests__/language.test.tsx` fails on any missing key, placeholder or tag mismatch. A missing Hindi string falls back to English at runtime.

## Dates and numbers

`src/lib/date.ts` takes month and weekday names from `date.*` keys (`monthShort`, `monthLong`, `weekdayLong`). Digits stay 0-9 and money keeps Indian grouping (`₹12,34,567`) in both languages.

## Where the language comes from

1. A change made while signed in that couldn't reach the server (sent at the next sign-in).
2. The account's `preferred_language` (`PATCH /auth/me { preferredLanguage }`, returned by `/auth/me` and login) — follows the user to every device.
3. The language picked on this device (Get Started's first page, which new installs see).
4. English — existing users see no change until they pick a language.

Switching calls `i18n.changeLanguage`, so every screen re-renders in place: no reload, no sign-out, navigation state kept.

## Fonts

Geist (the brand font) has no Devanagari glyphs, so Hindi text falls back to the system Devanagari font: Noto Sans Devanagari on Android, Kohinoor Devanagari on iOS. Avoid tight fixed `lineHeight` and `letterSpacing` on text that can be Hindi; the matras need the room.
